# V0.3 — Model-backed orchestration

Personal Ventures OS now has a real model-backed orchestration layer while keeping all external side effects disabled.

## Execution graph

```
Founder objective
  ↓
Deterministic safety router
  ↓
Chief of Staff planning model
  ↓
Selected specialist models
  ↓
QA model
  ↓
Chief of Staff synthesis model
  ↓
Human approval gate when required
```

The deterministic router remains in front of model execution. It decides the initial specialist set and risk/approval requirement. The model does not get permission to expand into arbitrary tools or venture scopes.

## Provider

The first provider adapter uses the OpenAI Responses API directly from the server.

Required runtime variables:

- `OPENAI_API_KEY`
- `PERSONAL_VENTURES_AGENT_MODEL`

Optional model overrides:

- `PERSONAL_VENTURES_ORCHESTRATOR_MODEL`
- `PERSONAL_VENTURES_SPECIALIST_MODEL`
- `PERSONAL_VENTURES_QA_MODEL`

The adapter requests strict JSON-schema outputs, disables provider-side storage for these calls, applies a timeout, caps output tokens and never exposes the API key to the browser.

## Agent phases

### Chief of Staff — planning
Turns the founder objective into success criteria and concrete assignments for only the specialist agents already selected by the deterministic router.

### Specialists
Run in parallel. Each receives:
- the selected venture context;
- the founder objective;
- the Chief of Staff plan;
- its own assignment;
- explicit side-effect guardrails.

### QA
Reviews specialist outputs for missing dependencies, unsupported claims, boundary violations, duplicated work and false claims of external execution.

### Chief of Staff — synthesis
Produces the founder-facing result and keeps sensitive actions in an approval list instead of claiming they happened.

## Persistence behavior

When the dedicated Personal Ventures Supabase project is configured:
- a task run is created before model execution;
- model/usage data is written to task steps;
- final result and QA state are persisted;
- sensitive objectives retain their approval request;
- failures are recorded.

When Supabase is not configured, the same orchestration can run in volatile mode. No fake persistence is shown.

## Cost controls

The engine limits specialist fan-out and model output sizes.

Optional controls:
- `PERSONAL_VENTURES_MAX_SPECIALISTS` (1–6, default 6)
- `PERSONAL_VENTURES_MAX_OUTPUT_TOKENS` (400–4000, default 1600)
- `PERSONAL_VENTURES_MODEL_TIMEOUT_MS` (10s–90s, default 45s)

Token counts are captured from the provider. Estimated USD cost remains zero until a pricing adapter is configured so the system does not store misleading cost estimates.

## Safety boundary

V0.3 has no external tools. It cannot publish, send, pay, delete, deploy to production or mutate third-party systems. Those capabilities belong to the connector/execution phases and must be approval-gated.
