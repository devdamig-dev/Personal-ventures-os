# V0.2 — Persistence and Approval Foundation

This phase makes Personal Ventures OS persistence-ready without forcing the dedicated Supabase project to stay active.

## What is implemented

- a server-side operations repository;
- creation of persisted task runs;
- persisted task steps derived from the deterministic routing plan;
- venture-scoped run history;
- approval request creation for sensitive objectives;
- human approve/reject decisions;
- audit events for run creation and approval decisions;
- explicit 503 fallback while the dedicated Supabase project is inactive;
- a system-status endpoint that reports persistence/model availability;
- operational telemetry columns for future provider/model/token/cost tracking.

## API surface

### `GET /api/system/status`

Returns runtime capability state. It never exposes secrets.

### `GET /api/runs?venture=gastropilot`

Returns persisted task runs for one venture.

### `POST /api/runs`

Example body:

```json
{
  "venture": "gastropilot",
  "objective": "Preparar el próximo experimento de onboarding",
  "title": "Onboarding experiment"
}
```

The route creates the run, task-step skeleton, optional approval request and audit event.

### `GET /api/approvals?venture=gastropilot&status=pending`

Lists approvals scoped to the selected venture.

### `PATCH /api/approvals/:id`

Example body:

```json
{
  "venture": "gastropilot",
  "decision": "approved"
}
```

Only `approved` and `rejected` are accepted.

## Safety properties

- Every write resolves the venture first.
- Approval decisions verify the approval's task run belongs to the selected venture.
- Avans Agency data is not queried or referenced.
- No external action is performed by this layer.
- When persistence is disabled, routes fail explicitly instead of pretending data was saved.

## Current runtime state

The repository code is ready, but the dedicated Personal Ventures Supabase project remains intentionally inactive/not provisioned. The existing `/api/router` route stays usable as the no-persistence planning fallback.

## Next phase

V0.3 will add model-backed agent execution behind the same run/step/approval model, while keeping external side effects disabled by default.
