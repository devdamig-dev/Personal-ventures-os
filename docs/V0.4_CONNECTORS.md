# V0.4 — Read-only connectors

V0.4 introduces an external tool layer without giving agents write access to third-party systems.

## Connector policy

Every connector is registered with:
- an explicit connector id;
- a fixed list of actions;
- a read-only mode;
- allowed agent ids;
- runtime configuration state.

The connector registry is authoritative. A model cannot invent a new connector or action and have it executed.

## Initial connectors

### GitHub

Read-only actions:
- `github.repo_summary`
- `github.file_text`
- `github.recent_commits`

Required runtime variable:
- `PERSONAL_VENTURES_GITHUB_TOKEN`

### Vercel

Read-only actions:
- `vercel.project_summary`
- `vercel.recent_deployments`

Required runtime variable:
- `PERSONAL_VENTURES_VERCEL_TOKEN`

Optional:
- `PERSONAL_VENTURES_VERCEL_TEAM_ID`

### Nexodg WP Central

Read-only bridge actions:
- `wp-central.sites`
- `wp-central.site_health`

Required runtime variables:
- `PERSONAL_VENTURES_WP_CENTRAL_URL`
- `PERSONAL_VENTURES_WP_CENTRAL_TOKEN`

The Personal Ventures side expects the following bridge contract:
- `GET /api/agent-bridge/sites`
- `GET /api/agent-bridge/sites/:siteId/health`

The bridge must be implemented and authenticated inside Nexodg WP Central before this connector is considered configured.

## Orchestration flow

The Chief of Staff can attach up to three read-only tool requests to each specialist subtask. The engine then:

1. validates the action against the connector registry;
2. validates the selected venture boundary;
3. validates agent permission;
4. executes only a registered GET/read action;
5. returns a connector observation;
6. supplies the observation to the specialist;
7. supplies all observations to QA and final synthesis.

Unavailable connectors return an explicit unavailable observation. Agents are instructed not to treat missing observations as verified facts.

## Security properties

- No connector mutation action exists in V0.4.
- Secrets remain server-side.
- Connector outputs never include authorization headers.
- Avans Agency remains outside the Personal Ventures boundary.
- A model request is not permission to execute an unregistered action.
- Connector failures do not silently become successful evidence.

## Next step

A later execution layer may introduce approval-gated write actions as separate capabilities. Read actions and write actions should remain separate registrations and separate policies.
